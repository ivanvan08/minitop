# Функції

Екран складається з шапки, таблиці процесів і нижнього рядка стану. Кадр
перемальовується кожні `refresh_ms`, диски перечитуються раз на
`disk_refresh_sec`.

## Шапка

| Панель | Що показує |
|---|---|
| `cpu` | смуга загального CPU; температура і uptime; load average 1/5/15; рядок GPU; кількість процесів і потоків; running і sleeping |
| `mem` | смуга RAM; used/total; available/free; cached/buffers; смуга swap; swap used/total |
| `disks` | фізичний диск: коротка назва, смуга, відсоток; під ним змонтовані файлові системи: точка монтування, used/total, відсоток |

Смуга: заповнена частина - щільні блоки, вільна - точки. Назва диска
вкорочується, зайві диски згортаються в `… +N`.

Температура - з `/sys`; без датчика стоїть прочерк. Рядок GPU з'являється,
коли GPU знайдено (`nvidia-smi` або sysfs); `gpu = false` вимикає пробу.

## Таблиця

| Колонка | Що показує |
|---|---|
| PID | ідентифікатор процесу |
| USER | власник; `root` має окремий колір |
| COMMAND | `comm`, а не `cmdline` |
| STATE | стан однією літерою з `/proc`: `R`, `S`, `D`, `Z`, `T`, `t`, `I`, `X` |
| CPU% | завантаження одного ядра; 100 - одне ядро повністю, більше 100 можливо |
| MEM | резидентна памʼять процесу (RSS) у МіБ |
| TIME+ | сумарний процесорний час, хвилини:секунди.сотих |
| FLAGS | теги в режимі 1, вердикт у режимах 2-3 |
| PERMS | `rwx`-біти виконуваного файлу; помаранчеві, якщо інші можуть писати |

Порядок фіксований; `column.<ім'я> = false` ховає колонку. Вузький термінал
прибирає колонки справа, крім FLAGS і PID; COMMAND тримає шість клітинок.
Нижче 60x18 - `terminal too small: WxH, need 60x18`.

## Керування

| Клавіша | Дія |
|---|---|
| `h`, `l`, `←`, `→` | колонка ліворуч або праворуч |
| `j`, `k`, `↓`, `↑` | рядок нижче або вище |
| `PgUp`, `PgDn` | сторінка вгору або вниз |
| `Home`, `End` | початок або кінець списку |
| `s` | сортувати за вибраною колонкою |
| `x` | kill |
| `f` | follow |
| `Esc` | зняти виділення рядка і follow |
| `q` | вихід |

Колонка підсвічується в шапці, рядок - фоном, перетин - сильнішим фоном.
У стані спокою рядка немає; перший `j` бере перший, `k` - останній.

`navigation = false` робить клавіші навігації інертними: лишається `q`, а
вже відкрите питання kill можна відповісти. Таблиця при цьому жива.

`s` сортує за вибраною колонкою: перший натиск на новій - спадання,
повторний - зростання. У шапці стоїть `↓` або `↑`; схована колонка
сортування передає його першій видимій.

## Kill і follow

`x` відкриває питання `SIGTERM PID COMM?  y / n`. `y` надсилає SIGTERM,
інша клавіша скасовує. Повторний `x` на ще живому процесі пропонує
SIGKILL. Ціль перевіряється за PID і `starttime`, тому PID, що встиг
перевикористатися, не постраждає.

`f` закріплює рядок за PID: виділення їде за процесом крізь перемальовки.
Повторний `f`, `Esc`, рух рядка або смерть процесу вимикають follow.

## Три режими

| Режим | Мережа | Що в FLAGS |
|---|---|---|
| 1 | немає | теги `DEL`, `TMP`, `MEMFD`, `NET` через кому, тьмяні; `-`, якщо тегів немає |
| 2 | decision-модель | рівень 1..10 цифрою: синя клітинка нижче порога, червона на порозі або вище; довірені показують `ok` |
| 3 | модель і LLM | нижче порога - синя цифра; на порозі або вище - тьмяна цифра, поки LLM думає, далі вердикт: 0 - синя, 1 - червона |

Поріг - `model.threshold`, типово 5. Нижче - синій текст на темно-синьому,
на порозі або вище - червоний на темно-червоному. Довірені C/E/H показують
`ok` приглушеним зеленим; процес без оцінки - тьмяний прочерк.

Якщо decision-модель увімкнена, але рушій не стартував (немає ключа або
libcurl), усі клітинки стають сірими прочерками. У режимі 3, коли модель
працює, а LLM не піднялася, рядок на порозі або вище помаранчевий.

**Звіт.** Кожен вердикт додає один JSON-рядок у `model.report_path` або
`llm.report_path`; `none` вимикає звіт. Модель пише `time`, `pid`, `comm`,
`level`, `model`; LLM додає `verdict`, `reason`, `detail`, токени і `cost`.

## Конфіг

Формат - `key = value`, коментар з `#`. Шлях -
`$XDG_CONFIG_HOME/minitop/config`, інакше `~/.config/minitop/config`;
`--config PATH` перекриває. Типовий файл створюється при першому запуску і
більше не переписується; поганий рядок зупиняє розбір, ключі вище
лишаються діючими.

| Область | Ключі | Що вирішує |
|---|---|---|
| Режим | `mode` | 1, 2 або 3; перекриває прапорці рушіїв |
| Оновлення | `refresh_ms`, `disk_refresh_sec` | інтервал кадру і перечитування дисків |
| Панелі | `show_portrait`, `gpu` | портрет `ceo` і рядок GPU |
| Таблиця | `sort_column`, `sort_desc`, `highlight_row`, `navigation`, `column.*` | початкове сортування, підсвітка рядка, навігація, набір колонок |
| Модель | `model.enabled`, `model.threshold`, `model.name`, `model.endpoint`, `model.key_file`, `model.resample_sec`, `model.max_per_pass`, `model.report_path`, `model.dry_run` | decision-модель |
| LLM | `llm.enabled`, `llm.name`, `llm.key_file`, `llm.min_level`, `llm.max_level`, `llm.resample_sec`, `llm.max_per_pass`, `llm.max_tokens`, `llm.report_path`, `llm.dry_run` | LLM-шар |

Повний перелік з поясненнями - у [config.example](config.example).
